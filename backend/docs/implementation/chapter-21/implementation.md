2. Model

2.1 Document

The model inherits from the project's shared UUID/timestamp foundations.

The fields are:

Field

Purpose

id

Resource identity

trip

Trip whose itinerary is shared

share_token

Public capability secret

is_active

Revocation state

expires_at

Optional expiration

created_at

Creation timestamp

updated_at

Modification timestamp

The current model defines share_token as unique, indexed, and generated by _generate_share_token. fileciteturn130file0L2-L2

The token generator is:

def _generate_share_token() -> str:
    return secrets.token_urlsafe(32)

The resulting token is therefore intentionally separate from the UUID primary key.

2.2 Validity Rule

Document.is_valid is the model-level source of truth for whether the link is currently usable.

Conceptually:

inactive → invalid
expired  → invalid
otherwise → valid

The current implementation checks:

if not self.is_active:
    return False

if self.expires_at and self.expires_at < timezone.now():
    return False

return True

This prevents callers from implementing inconsistent partial validity checks. fileciteturn130file0L2-L2

4. Services

4.1 create_share_link

The service creates the persistent capability record.

Current signature:

create_share_link(
    *,
    trip: Trip,
    expires_at: datetime | None = None,

It delegates token generation to the model field default and stores the optional expiration. fileciteturn131file0L2-L2

4.2 revoke_share_link

Revocation is deliberately implemented as a state transition:

active → inactive

Only is_active and updated_at are persisted.

The current service therefore does not destroy the link record. fileciteturn131file0L2-L2

4.3 generate_itinerary_pdf

The current PDF pipeline is:

Trip
 ↓
get_trip_itinerary()
 ↓
ItineraryDaySerializer
 ↓
BytesIO
 ↓
ReportLab canvas
 ↓
PDF bytes
 ↓
FileResponse

The implementation:

uses A4,

sets the PDF title,

writes trip title and dates,

writes each itinerary day,

writes summaries,

writes itinerary items,

includes time, description, estimated cost, and destination where available,

handles page breaks,

saves the PDF to the in-memory buffer,

rewinds the buffer,

returns a FileResponse.

No file is persisted to disk or database. fileciteturn131file0L2-L2

5. Selector

get_active_document_by_token

The selector performs:

token lookup,

is_active=True filtering,

select_related("trip"),

final is_valid verification.

Unknown, revoked, and expired documents all resolve to None.

The current selector is therefore the single lookup boundary used by the public view. fileciteturn134file0L2-L2

The view verifies both:

the document belongs to that trip.

Only then is revocation allowed.

This prevents a user from revoking another user's share link. fileciteturn132file0L2-L2

7.4 PublicSharedItineraryView

This is deliberately:

permission_classes = (
    permissions.AllowAny,
)

The share token itself acts as the capability.

The view:

resolves the active document,

returns 404 when it is unavailable,

gets the trip,

obtains the itinerary through the existing selector,

builds the minimal public payload,

The current implementation therefore separates authentication from capability possession. fileciteturn132file0L2-L2

9. Why <str:token> Matters

The share token is generated with secrets.token_urlsafe(32).

It is not a UUID.

Therefore:

<uuid:token>

would be the wrong Django converter.

The current repository correctly uses:

<str:token>
